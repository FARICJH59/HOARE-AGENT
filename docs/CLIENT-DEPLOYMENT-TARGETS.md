# HOARE Client Deployment Targets

**Provenance:** 2026-09-15

## Default

For ordinary client application projects generated by HOARE, the default cloud deployment target is:

```text
cloudflare-prod
```

This means the resolved target is:

```text
provider = cloudflare
environment = prod
```

The default is a **target preference**, not a deployment authorization. AEGIS, project lifecycle, credentials, verification, and any required human authorization remain authoritative.

## Why Cloudflare is the default

Cloudflare Workers provides a globally distributed serverless execution platform and supports JavaScript/TypeScript, Python, Rust, and other application stacks. citeturn0search7

For multi-tenant client projects, Cloudflare Workers for Platforms provides isolated customer Workers, dispatch namespaces, dynamic routing, per-customer limits, and bindings to resources such as KV, D1, R2, Queues, Workflows, Containers, and private-network services. citeturn0search1turn0search3turn0search8

Cloudflare also documents programmatic deployment of customer Workers through its API/SDK, which fits HOARE's provider-adapter model. citeturn0search5

## Client override

The default must never lock a customer into Cloudflare.

Examples:

```text
cloudflare-prod   ← default
aws-prod
aws-staging
azure-prod
gcp-prod
onprem-prod
edge-pi5
jetson-edge
```

A vertical may also override the cloud default when the workload has physical, edge, air-gapped, regulatory, latency, or hardware constraints.

For example, an AesirGrid physical-control component should not be forced onto Cloudflare merely because the client application/control-plane default is Cloudflare.

## Governance

The deployment path remains:

```text
CLIENT PROJECT
      ↓
HOARE PROJECT BUILDER
      ↓
resolve_client_deployment_target()
      ↓
cloudflare-prod (default)
      ↓
BUILD
      ↓
TEST
      ↓
VERIFY
      ↓
AEGIS POLICY REVIEW
      ↓
STAGED
      ↓
EXPLICIT AUTHORIZATION
      ↓
DEPLOYMENT ADAPTER
      ↓
CLOUDFLARE
```

Cloudflare credentials must never be placed in generated customer source code or exposed to the browser. Cloudflare's current documentation recommends scoped API tokens for automation; Workers permissions can be scoped to the required Worker/resource, and API tokens are intended for CI/CD systems, agents, scripts, and Wrangler automation. citeturn0search12turn0search13

For Workers for Platforms, Cloudflare's documented production pattern uses a permanent Cloudflare account and appropriate API authentication rather than temporary preview credentials. citeturn0search18

## Implementation

The target resolver is:

```text
backend/hoare_engine/client_deployment_target.py
```

and is covered by:

```text
backend/tests/test_client_deployment_target.py
```

The resolver intentionally performs **no deployment**. It only resolves the requested target so later governed deployment stages have an explicit provider/environment contract.
